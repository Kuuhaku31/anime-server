# 数据库结构

`<数据文件夹>/main.db` 是 SQLite 数据库文件, 包含以下表:

## `file`

文件表, 保存文件本身信息, 不关心文件地址.

| 字段                  | 类型 | 约束                    | 说明                                                 |
| --------------------- | ---- | ----------------------- | ---------------------------------------------------- |
| pre16mib_md5          | text | primary key             | 文件至多前 16MiB 的 MD5                              |
| size                  | int  | not null                | 文件大小, 单位字节                                   |
| audio_stream_index    | int  |                         | 默认音轨的容器全局流索引, null 表示不选择音轨        |
| subtitle_stream_index | int  |                         | 默认字幕轨的容器全局流索引, null 表示关闭字幕        |
| ddp_epi_id            | int  |                         | DandanPlay Episode ID, null 表示没有匹配到           |
| danmaku_offset        | real | not null, default = 0.0 | 弹幕偏移, 单位秒, > 0 表示需要弹幕推迟显示, < 0 反之 |
| watch_pos             | real |                         | 播放进度, 单位秒                                     |
| watched_datetime      | text |                         | 最近一次播放时间, ISO 8601 格式                      |

## `file_path`

文件路径表, 保存文件所在目录的绝对地址与拆分文件名, 允许同一个文件有多个路径.

| 字段         | 类型 | 约束     | 说明                                        |
| ------------ | ---- | -------- | ------------------------------------------- |
| path         | text | not null | 文件所在目录的绝对地址, 如 `/media/series`  |
| name_no_ext  | text | not null | 文件名, 不包含扩展名                        |
| extension    | text | not null | 文件扩展名, 不包含点                        |
| pre16mib_md5 | text | not null | 文件至多前 16MiB 的 MD5, 外键关联 `file` 表 |

`path`, `name_no_ext`, `extension` 组成复合主键.

`path` 不包含文件名. 根目录视频保存 `/media`, 而不是空字符串.
完整文件地址通过目录和 `name_no_ext.extension` 拼接, 例如 `/media/series/episode.mkv`.
地址属于服务进程所在的文件系统, 容器中保存容器地址, 不是宿主机挂载源地址.
播放前仍会规范化完整地址并确认其位于媒体根目录, 不允许通过符号链接访问根目录外文件.
旧相对路径记录在下一次成功扫描时被绝对路径记录替换, 文件指纹及业务信息仍保留.

该表在定时或手动扫描成功后按目录列表增量更新.
扫描前读取全部已知路径, 只有新地址计算前缀 MD5, 已存在地址默认内容未变,
不会检查大小, 修改时间或原地替换文件. 改名或移动后的新地址会重新计算哈希.
事务只插入新路径和删除失效路径, 不清空整张表.
没有现存路径的 `file` 记录仍保留, 因此文件重新出现时可恢复进度和识别信息.

`repository::update` 接收 `ScanChanges`, 将新增和删除的完整文件地址拆成上述复合主键,
独立在同一事务中依次删除失效路径, 插入或更新文件记录, 插入新增路径.
不调用旧写入函数. 无效地址或写入冲突会报错, 不保留部分更新.
已有文件指纹只更新大小, 不覆盖轨道偏好, 观看进度或识别信息.
此函数不探测媒体轨道, 当前 `ScannedFile` 不携带轨道配置, 因此新记录的两个轨道字段均为 null.
`get_paths` 返回拼接后的完整文件地址, 用于与扫描得到的文件地址匹配.

## 初始化与持久化边界

后端启动时直接执行 `backend/sql/init.sql`, 使用 `CREATE TABLE IF NOT EXISTS`
创建上述两张表及索引. 不使用 SQL 迁移框架.
轨道偏好列会在初始化 SQL 后按需通过 `ALTER TABLE` 添加, 保留已有文件行和观看进度.

`watch_pos` 始终保存原视频的绝对播放时间, 不是某个 HLS 会话从零开始的局部时间.
换流, 会话释放和缓存淘汰不会删除进度, 文件识别信息或弹幕偏移.
首次扫描新文件时会按 default 标记选择音轨, 没有 default 则选第一条; 字幕选 default 或 forced,
没有匹配字幕则保存 null. 用户在播放器切换轨道或关闭轨道时, 显式选择会覆盖对应数据库字段.
默认播放由服务端直接读取 `watch_pos`, 客户端不先读取或回传历史进度.
距结尾不足 2 秒的记录从 0 开始; 换轨提交的当前绝对位置只作为新会话目标.

媒体元数据和探测错误只在服务进程内缓存, 不写入 SQLite.
共享 HLS 缓存在 `/cache/playback/<variant-key>/` 持久保存, 不写入数据库或 JSON 状态文件.
活动集合按播放配置去重, 只管理当前客户端租约和正在停止的任务, 不是持久缓存索引.
最后一个租约释放后, 在分片边界停止并移除活动元素, 部分和完整缓存都可留在磁盘.
重启时根据 playlist 和媒体文件恢复连续前缀及完成标记, 不重建客户端会话或自动续接.
新的点播请求才把磁盘缓存重新加入活动集合, 不需要新增数据库字段或迁移.
字幕和字体中间文件分别位于 `/cache/subtitles` 和 `/cache/fonts`, 生成任务结束后删除.

播放配置使用 `pre16mib_md5` 关联源视频, 轨道选择和编码配置版本用于区分缓存变体.
文件前 16 MiB 之后的改动不会改变此标识, 不会自动使播放缓存失效.
